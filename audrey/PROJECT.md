# Audrey’s Heart — regional travel journal

Version: 1 (2026-09-07). Public URL: https://stirman.net/audrey/ (GitHub Pages, `stirman/stirman.github.io`, `master` branch). Scope is this subpath only; preserve the existing homepage and all other projects.

## Files
- `index.html`: accessible page structure, hero, map, summary, journal and disclosure.
- `styles.css`: responsive cream / rose travel-journal design; system/Georgia fallbacks; optional Google Fonts.
- `app.js`: no-build renderer, JSON loading, validation, map filtering and grouped regional markers, chronological journal.
- `data/coins.json`: maintained separately by the source-data/updater owner. No sample public data is generated by the frontend.

## Public data contract
`{updatedAt, coins:[{id,name,color,status,distanceMiles,sourceUrl,logs:[{id,date,type,text,cacheName,location,lat,lon,precision,sourceUrl}]}]}`.

IDs are public TB reference IDs, never private tracking codes. Coin IDs and each coin’s log IDs must be unique strings. `color` accepts a six-digit hex color or uses a fallback. `distanceMiles` is a nonnegative number or null (unknown). Coordinates are numbers or null; invalid/out-of-range coordinates are not mapped. Dates may be ISO dates or timestamps. Journal logs are rendered newest first; same-day ordering reverses the stored oldest-first source sequence. Map routes and stored source data remain oldest first. Unknown dates appear last. Optional enrichment fields `event` and `coordinateSource` are rendered as original event text and a regional geocoding source link.

Seven unique trackables are expected, including TBB8FJ3. The original seven inputs contained one duplicate; TBB8FJ3 was added separately. The app derives actual totals from JSON; duplicate public IDs produce an explicit error instead of inflating totals. Three coins have history and four await their first public log; derive counts from live data. The app never invents waiting-coin locations.

## Accuracy / privacy
- Regional overview, not exact cache mapping. City/region centers can repeat across numerous logs. Exact cache maps require Geocaching authentication and have not been accessed.
- One marker per coin/coordinate pair, with a regional log count and latest log summary; all logs remain individually available in the journal. Clicking a journal location opens its region’s summary marker.
- Dashed colored connections are illustrative, not actual paths. Coordinates stay in a shared single world; long cross-world connections are not flight routes.
- “Mapped travel logs” counts located logs, not unique geographic places. Unknown-location logs remain in the journal.
- Miles are summed only from source-recorded numeric distances, never estimated from lines. Missing distance is excluded, not treated as known zero. Hovering the total reveals source coverage.
- Strings are inserted with `textContent`; source links accept HTTP(S) only. No credentials, cookies, secret codes, or authenticated source access are required.

## Runtime and failure behavior
Leaflet 1.9.4 comes from unpkg; OpenStreetMap tiles use `https://tile.openstreetmap.org/{z}/{x}/{y}.png` with attribution. Google Fonts are optional. Network access is required for map assets. CARTO was rejected after visual verification showed API-key watermarks despite successful HTTP responses.

The public JSON is fetched with cache busting and no-store, with a 15-second timeout. Empty data, invalid data, HTTP failure, missing Leaflet, missing map locations, stale/unknown update time and missing distances have distinct visible states. Failed data loads offer a retry. A separate tile-health warning tracks current failed tile elements and clears as they load or leave the viewport; it never replaces the selected journey label.

## Updates and deployment
Update source history only through the parent-owned updater and validate its public JSON before deployment. No API keys are used by the frontend. Existing repository owner controls GitHub Pages publication. After reviewing the frontend and data together, owner can stage only intended `audrey/` files, commit and push using the existing deployment workflow. Verify the HTTPS page and JSON after Pages propagation before declaring the site live. Change CSS/JS query versions in HTML when shipping later behavior changes.

## Known limits
Map/data/CDN availability is network-dependent. Region-level markers deliberately cannot locate a physical geocache. Coin cards scroll in the desktop panel; mobile shows a two-column card grid below the map. The journal shows all source logs without pagination. No persistent browser storage or analytics.
